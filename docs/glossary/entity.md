# 实体 (Entity)

## 一句话定义

实体是**有唯一标识**的对象：只要标识相同，就认为是同一个东西，哪怕其他属性全变了。

判断标准很简单——问自己：「属性改光了，这还是同一个它吗？」

## 具体例子

商品 `SKU-1001` 改过名字、改过售价、改过规格，它**仍然是同一个商品**，
因为它的 `id` 没变。所以「商品」是实体。

对比：一个「金额 100 元」改成「金额 200 元」，那就**不是同一个金额**了，
它没有标识、靠值来判断相等。这种叫[值对象](value-object.md)。

代码上的体现是 `equals`/`hashCode` 的写法：

```java
// 实体：只按 id 判断相等
@Override
public boolean equals(Object o) {
    return o instanceof Product other && Objects.equals(id, other.id);
}
```

## 在本项目里怎么用

my-erp 中典型的实体：

| 实体 | 标识 |
| --- | --- |
| 商品 Product | 商品编码 / id |
| 客户 Customer | 客户 id |
| 销售订单 SalesOrder | 订单号 |
| 采购订单 PurchaseOrder | 订单号 |

注意「库存余额 InventoryBalance」是**商品 + 仓库**的组合，
它更像是以 `(productId, warehouseId)` 为标识的实体，而不是一个普通数值。

## 常见误解

- **误解一**：有 `id` 字段就叫实体。关键不是有没有字段，而是**相等性是否依赖它**。
- **误解二**：实体必须有数据库主键。领域概念上的标识和数据库主键可以一致，也可以不同
  （比如业务上用「订单号」作为标识，数据库另有自增主键）。
