# 聚合 / 聚合根 (Aggregate / Aggregate Root)

## 一句话定义

聚合是**一组必须放在一起才讲得通、必须一起保证正确**的对象的边界；
聚合根是这个边界上唯一的出入口，外部只能通过它来访问内部对象。

一句话记法：**聚合是「一致性边界」，聚合根是「边界上的门」。**

## 具体例子

一张销售订单和它的明细行：

```
SalesOrder (聚合根)
├── orderNo, customerId, status
└── List<OrderLine>   ← 明细行属于这个聚合
        ├── productId
        ├── quantity
        └── unitPrice
```

为什么明细行不自己独立出去？因为「订单总金额 = 所有明细行金额之和」这条规则
要求订单和明细**任何时刻都保持一致**。如果允许别人绕过订单直接改某条明细，
总金额就可能对不上——业务数据就烂了。

所以规则是：

```java
// 允许：通过聚合根操作，根可以在内部维护一致性
order.addLine(product, qty, price);   // 内部顺带更新总额

// 不允许：外部直接拿到明细行去改
orderLine.setQuantity(5);   // ❌ 绕过了订单，总额不会更新
```

判断边界在哪，问一句：**哪些数据必须「同时正确」？** 必须同时正确的，放一个聚合里。

## 在本项目里怎么用

| 聚合根 | 内部包含 | 要维护的一致性 |
| --- | --- | --- |
| SalesOrder | OrderLine 列表 | 总额 = 明细之和；已确认订单不可增删行 |
| PurchaseOrder | PurchaseOrderLine 列表 | 同上 |
| InventoryBalance | 无（本身即根） | 数量不为负 |

划分原则：**聚合尽量小**。明细行数量多时不要整张订单一次性加载，
但本项目是示例项目、数据量小，按订单聚合成一个整体反而更直观易懂。

## 常见误解

- **误解一**：聚合 = 数据库表的主外键关系。不一样。外键是存储层的约束，
  聚合是**业务一致性**的边界；有些外键关系并不需要放进同一个聚合。
- **误解二**：聚合越大越好，一次全捞出来省事。聚合越大，并发冲突和加载开销越大，
  应尽量小。
- **误解三**：聚合根不能返回内部对象。可以返回，但**只读**使用；
  要修改必须走聚合根的方法。
